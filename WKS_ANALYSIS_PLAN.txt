1. EXECUTIVE SUMMARY
==============================================================================
The san-scraper (salvage) project is NOT exclusively a WKS-to-JSON converter.
It is a multi-format defensive binary file recovery engine developed for forensic
salvage of damaged, undocumented, or legacy binary streams (PS 02: Salvage).
It implements unified recovery pipelines across five distinct binary formats:
  1. Lotus 1-2-3 (.WKS / .WK1) - Legacy spreadsheet record stream
  2. Quake PAK (.PAK)          - id Software game archive with directory lumps
  3. LIBRA-98 (.LIB)           - Legacy telemetry/database with CRC checks
  4. LABLOG (.LAB)             - Block-framed laboratory journal with CRC32 isolation
  5. VAULT (.VLT)              - Obfuscated archive with PackBits RLE & XOR unmasking
  6. UNKNOWN / EMPTY           - Defensive catch-all stream parser

Core Invariants of the Entire Project:
  - 100% offline, pure Python 3.13 standard library (zero external pip dependencies).
  - Bounded binary reading (BoundedBinaryReader) to prevent memory allocation bombs.
  - Per-file isolation (a broken, malicious, or malformed file never halts processing).
  - Unified forensic JSON reporting (individual <filename>.json and run report.json).

Current WKS Component Rating:
  - Binary/structural correctness: 9-10 / 10
  - Lossless record preservation:   4-5 / 10  (payloads truncated at 32 bytes)
  - Formula preservation:           3-4 / 10  (only cached float preserved, bytecode lost)
  - Unknown opcode preservation:    5-6 / 10  (stored but truncated)
  - Semantic correctness:           6-7 / 10  (missing 0x0008, 0x000B, formulas)
  - Overall conversion quality:     7-7.5 / 10

Target WKS Component Rating:
  - Binary/structural correctness: 10 / 10
  - Lossless record preservation:  10 / 10   (100% full raw byte retention)
  - Formula preservation:          10 / 10   (formula string + RPN tokens + bytecode)
  - Unknown opcode preservation:   10 / 10   (complete payload retention)
  - Semantic correctness:          9+ / 10   (decoded 0x0008, 0x000B, formulas)
  - Overall conversion quality:    9.5+ / 10

5. ROOT CAUSE ANALYSIS OF WKS ISSUES
==============================================================================

Issue 1: Payload Truncation (P0 - CRITICAL)
- Source: src/formats/wks.py line 265:
    fields.update({
        "record_type": f"UNKNOWN_OPCODE_0x{opcode:04X}",
        "raw_hex": payload_bytes[:32].hex(),   <-- HARD-CODED 32-BYTE SLICE!
    })
- Cause: Development display truncation that leaked into the data pipeline.
- Fix: Replace with 100% complete payload hex string.

Issue 2: Formula Expression Discarded (P0 - CRITICAL)
- Source: src/formats/wks.py lines 248-260:
    Reads 1B format, 2B col, 2B row, 8B float cached value.
    Completely discards bytes 13..payload_len (expression length & RPN tokens).
- Cause: Formula tree marked as "inert data" for security without preserving bytecode.
- Fix: Separate into:
    - cached_value: 8B double float
    - formula_raw_hex: complete raw bytecode hex
    - formula_tokens: parsed list of RPN tokens
    - formula: human-readable expression string (e.g., "+B4*1.05")

Issue 3: Opcode 0x000B Unresolved (P1 - HIGH)
- Reality: Official Lotus 1-2-3 specification (WSFF1.TXT) defines opcode 0x000B
  as NRANGE (Named Range).
- Wire Layout (24 bytes):
    Offset 0x00..0x10: Range Name (16 bytes, ASCII null/space-padded)
    Offset 0x10..0x12: Start Column (uint16)
    Offset 0x12..0x14: Start Row (uint16)
    Offset 0x14..0x16: End Column (uint16)
    Offset 0x16..0x18: End Row (uint16)
- Significance: In Lotus 1-2-3, macros are invoked by executing named ranges
  (e.g., \A, ADD, A-SORT, D-LOOP in COUPONS.WKS). Decoding 0x000B extracts the
  entire macro entry point table!

Issue 4: Opcode 0x0008 Unresolved (P1 - HIGH)
- Reality: Official Lotus 1-2-3 specification defines opcode 0x0008 as COLW
  (Column Width).
- Wire Layout (3 bytes):
    Offset 0x00..0x01: Column index (uint16)
    Offset 0x02:       Column width in character spaces (uint8, default 9)
- Matches data observed in COUPONS.WKS and public_sample.wks (e.g., 000009 -> Col 0, Width 9).

7. ROUND-TRIP RECONSTRUCTION & VALIDATION STRATEGY
==============================================================================
To mathematically guarantee that the conversion is lossless, implement:
  src/reconstructor.py (WksReconstructor)

Verification Flow:
  Original .WKS
       |
       v  WksParser.parse()
  Lossless JSON
       |
       v  WksReconstructor.reconstruct()
  Reconstructed .WKS Bytes
       |
       v  Binary Comparison
  sha256(Original) == sha256(Reconstructed)

Reconstruction Invariants:
  1. For every record in JSON:
     Header = struct.pack("<HH", opcode, len(payload_bytes))
     Payload = bytes.fromhex(record["data"]["raw_payload"])
  2. Sequential concatenation must produce an exact byte-for-byte replica.

Phase 1: Zero-Loss Raw Payload Invariant (P0)
- Target: src/formats/wks.py
- Action: Remove [:32] slice. Store 100% payload in raw_payload and raw_hex.
- Risk: LOW.

Phase 2: First-Class Decoders for 0x0008 & 0x000B (P1)
- Target: src/formats/wks.py
- Action: Decode COLUMN_WIDTH (<HB) and NAMED_RANGE (<16sHHHH).
- Risk: LOW.

Phase 3: Modular Formula Tokenizer (P0)
- Target: New file src/formats/wks_formula.py + hook in src/formats/wks.py
- Action: Disassemble Lotus RPN bytecode into tokens and formula string.
- Invariant: If token disassembly fails, fallback gracefully to raw bytecode
  preservation without raising exceptions.
- Risk: LOW.

Phase 4: Round-Trip Reconstructor Tooling
- Target: New file src/reconstructor.py + tests/test_wks_roundtrip.py
- Action: Implement binary synthesis from JSON and assert SHA-256 equivalence.
- Risk: NONE (read-only verification tool).

Phase 5: Full Regression Testing
- Target: Full test discovery across tests/
- Assert all 64 existing unit/fuzz/robustness tests pass without regression.
- Execute demo/run_demo.bat to verify end-to-end operational pipeline.
